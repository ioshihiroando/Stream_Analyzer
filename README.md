# Потоковый анализатор файлов

Потоковый анализатор файлов журналов событий на Python.
Программа обрабатывает файлы в форматах CSV и JSONL, проверяет корректность записи событий и формирует отчёт со статистикой в формате JSON.

---

## Возможности

- Построчное чтение файлов в форматах `CSV` и `JSONL` без загрузки всего файла в память.
- Обработка нескольких файлов одного формата за раз.
- Проверка записей событий на корректность.
- Подсчёт общего количества событий.
- Подсчёт количества событий каждого уровня.
- Подсчёт количества событий каждого источника.
- Вывод top-5 источников ошибок уровня `ERROR`/`CRITICAL`
- Вывод первой и последней временных меток.
- Режим `--skip-invalid` для пропуска некорректных записей событий.
- Формирование отчёта в формате `JSON`.
- Объединение статистики нескольких файлов.
- Ведение журнала работы программы `logs/streamstats.log`

## Использование
Общий формат команды:
```bash
python -m streamstats analyze INPUT [INPUT ...] --format csv|jsonl --output REPORT.json --skip-invalid
```
- `INPUT [INPUT ...]` - путь к входному файлу. Можно указать несколько файлов одного формата.
- `--format csv|jsonl` - формат входных файлов указывается строго `csv` или `jsonl`.
- `--output REPORT.json` - путь файла отчёта (стандартное значение: `/lab_02/reports/report.json`)
- `--skip-invalid` - обработать файлы, пропуская некорректные значения

Пример с несколькими обрабатываемыми файлами:
```bash
python -m streamstats analyze tests/data/sample.jsonl tests/data/clean_payments.jsonl --format jsonl
```

Пример с указанием пути файла отчёта:
```bash
python -m streamstats analyze tests/data/sample.csv --format csv --output other_reports/new_report.json
```

Пример с пропуском некорректных значений:
```bash
python -m streamstats analyze tests/data/types_invalid.jsonl --format jsonl --skip-invalid
```

## Форматы входных данных

### CSV
CSV-файл должен содержать заголовок со следующими полями:

| Поле        | Описание                                                         |
|-------------|------------------------------------------------------------------|
| `timestamp` | Временная метка в формате ISO 8601                               |
| `level`     | Уровень события: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `source`    | Источник события (является непустой строкой)                     |
| `message`   | Текст сообщения (строка)                                         |

### JSONL
Каждая строка содержит отдельный JSON-объект с данными одного события.

Пример:
```
{"timestamp":"2026-10-17T10:00:00+03:00","level":"INFO","source":"api","message":"Приложение запущено"}
{"timestamp":"2026-10-17T10:01:00+03:00","level":"ERROR","source":"database","message":"Ошибка подключения"}
```

### Особенности значений полей:
- Временная метка без часового пояса считается временем UTC.
- `Z` в конце временной метки обозначает время UTC.
- Если во временной метке отсутствуют часы, минуты и секунды, то значение каждого принимается за `00`.
- Пробел вместо `T` допускается, то есть варианты `2026-10-18 14:30:00` и `2026-10-18T14:30:00` валидны.
- Дата указывается строго в формате `YYYY-MM-DD`. Другие варианты будут считаться невалидными.
- Регистр значения `level` не важен, но не допускается наличие лишних символов (в том числе пробела).
- Регистр значения `source` имеет значение, но пробелы на краях строки не считаются, то есть `"api"` и `"    api   "` являются одним и тем же источником.

## Результат работы
Программа формирует отчёт в формате JSON в следующей структуре:
```json
{
  "event_total_count": 10,  
  "event_by_level": {     
    "INFO": 3,
    "DEBUG": 1,
    "ERROR": 4,
    "WARNING": 1,
    "CRITICAL": 1
  },
  "event_by_source": {      
    "auth": 3,
    "api": 2,
    "db": 2,
    "payments": 2,
    "cache": 1
  },
  "top_error_sources": {    
    "db": 2,
    "payments": 2,
    "auth": 1
  },
  "first_timestamp": "2025-01-15T07:00:05+00:00",  
  "last_timestamp": "2025-01-15T10:08:00+00:00",  
  "skipped_events": 0      
}
```
При обнаружении некорректной записи программа по умолчанию прекращает обработку и сообщает об ошибке. При использовании --skip-invalid некорректные записи пропускаются, а их количество включается в отчёт.
